# Продуктовая Спецификация

## 1. Описание Продукта

**Z.ai Chat** — это веб-приложение для интерактивного общения с AI-ассистентом на базе моделей GLM (General Language Model). Приложение предоставляет удобный интерфейс чата с возможностью настройки параметров генерации и выбора различных AI-моделей.

### Для кого это приложение?
- Разработчики, тестирующие AI-модели
- Пользователи, которым нужен доступ к различным GLM-моделям
- Команды, работающие с AI-ассистентами
- Исследователи, сравнивающие поведение разных моделей

### Какую проблему решает?
- Упрощает доступ к GLM-моделям через веб-интерфейс
- Позволяет быстро переключаться между моделями разной мощности
- Предоставляет единый интерфейс для работы с AI без необходимости настройки API-клиентов
- Дает возможность настраивать параметры генерации под конкретные задачи

### 2.1 Чат с AI

**Что может делать пользователь:**
- Отправлять текстовые сообщения AI-ассистенту
- Получать ответы в режиме реального времени (без streaming на данный момент)
- Просматривать историю сообщений в виде чата
- Видеть форматированный текст с поддержкой Markdown
- Очищать историю чата одним нажатием
- Видеть индикатор загрузки во время генерации ответа
- Получать понятные сообщения об ошибках с возможностью их закрыть

**User Stories:**

1. **US-1.1: Отправка сообщения**
   - Как пользователь, я хочу отправить сообщение AI, нажав Enter или кнопку Send
   - Чтобы быстро взаимодействовать с ассистентом без лишних действий
   - **Acceptance Criteria:**
     - Message отправляется при нажатии Enter (без Shift)
     - Message отправляется при клике на кнопку Send
     - Поле ввода очищается после отправки
     - Сообщение появляется в истории чата

2. **US-1.2: Просмотр истории**
   - Как пользователь, я хочу видеть всю историю сообщений
   - Чтобы контекст разговора не терялся
   - **Acceptance Criteria:**
     - Все сообщения отображаются в хронологическом порядке
     - Сообщения пользователя и AI визуально различаются
     - Список автоматически прокручивается к новому сообщению

3. **US-1.3: Очистка чата**
   - Как пользователь, я хочу очистить историю чата
   - Чтобы начать новый разговор с чистого листа
   - **Acceptance Criteria:**
     - Кнопка очистки доступна в header
     - При клике все сообщения удаляются
     - Появляется пустое состояние "Start a conversation"

4. **US-1.4: Обработка ошибок**
   - Как пользователь, я хочу видеть понятные сообщения об ошибках
   - Чтобы понимать, что пошло не так
   - **Acceptance Criteria:**
     - Ошибки отображаются в красном баннере
     - Есть кнопка для закрытия ошибки
     - Текст ошибки информативен

5. **US-1.5: Индикация загрузки**
   - Как пользователь, я хочу видеть, что AI генерирует ответ
   - Чтобы понимать, что процесс идет
   - **Acceptance Criteria:**
     - Показывается анимированный индикатор при загрузке
     - Кнопка Send блокируется во время загрузки
     - Индикатор исчезает после получения ответа

### 2.2 Настройки API

**Какие настройки доступны:**
- **API Key** — ключ авторизации для доступа к API
- **Model** — выбор AI-модели из 4 доступных
- **Max Tokens** — лимит длины ответа (null = без ограничений)
- **Temperature** — креативность генерации (0.0 - 2.0)
- **Stop Sequences** — последовательности для остановки генерации
- **Response Format** — формат ответа (Text или JSON)

**User Stories:**

6. **US-2.1: Настройка API Key**
   - Как пользователь, я хочу указать свой API ключ
   - Чтобы авторизоваться в сервисе
   - **Acceptance Criteria:**
     - Поле для ввода API ключа
     - Возможность скрыть/показать ключ
     - Валидация на пустое значение

7. **US-2.2: Выбор модели**
   - Как пользователь, я хочу выбрать AI-модель
   - Чтобы использовать подходящую модель для моей задачи
   - **Acceptance Criteria:**
     - Dropdown с 4 моделями
     - Отображается название и уровень мощности
     - Выбранная модель применяется к следующим запросам

8. **US-2.3: Настройка Temperature**
   - Как пользователь, я хочу настроить temperature
   - Чтобы контролировать креативность ответов
   - **Acceptance Criteria:**
     - Slider от 0.0 до 2.0
     - Отображение текущего значения
     - Значение сохраняется при Save

9. **US-2.4: Ограничение токенов**
   - Как пользователь, я хочу ограничить длину ответа
   - Чтобы контролировать расходы и время генерации
   - **Acceptance Criteria:**
     - Поле для ввода числа
     - Пустое поле = без ограничений
     - Валидация на числовое значение

10. **US-2.5: Формат ответа**
    - Как пользователь, я хочу выбрать формат ответа (Text или JSON)
    - Чтобы получать ответы в удобном формате для моих задач
    - **Acceptance Criteria:**
      - Два chip-переключателя: Text и JSON
      - Только один формат может быть выбран
      - Выбор сохраняется при Save

11. **US-2.6: Сохранение настроек**
    - Как пользователь, я хочу сохранить настройки
    - Чтобы они применялись к будущим запросам
    - **Acceptance Criteria:**
      - Кнопка Save сохраняет настройки
      - Кнопка Cancel отменяет изменения
      - Диалог закрывается после Save/Cancel

### Сценарий 1: Отправка сообщения

**Actor:** Пользователь  
**Goal:** Получить ответ от AI-ассистента  
**Preconditions:** Приложение открыто, API ключ настроен

```
Main Flow:
1. Пользователь вводит текст в поле ввода
2. Пользователь нажимает Enter или кнопку Send
3. Сообщение появляется в истории чата (справа)
4. Показывается индикатор загрузки
5. AI генерирует ответ
6. Ответ появляется в истории чата (слева)
7. Индикатор загрузки исчезает
8. Список прокручивается к новому сообщению

Alternative Flows:
3a. Если сообщение пустое → отправка блокируется
5a. Если ошибка API → показывается error banner
5b. Если timeout → показывается ошибка "Request timeout"
```

### Сценарий 2: Смена модели AI

**Actor:** Пользователь  
**Goal:** Изменить AI-модель для будущих запросов  
**Preconditions:** Приложение открыто

```
Main Flow:
1. Пользователь нажимает кнопку Settings (⚙️) в header
2. Открывается диалог Settings
3. Пользователь кликает на dropdown Model
4. Показывается список моделей:
   - GLM-4 32b (Супер легкая, слабая и дешевая)
   - GLM-4.5 Air (Слабая)
   - GLM-4.7 (Средняя)
   - GLM-5 (Сильная)
5. Пользователь выбирает модель
6. Пользователь нажимает Save
7. Диалог закрывается
8. В header отображается новая модель
9. Все последующие запросы используют новую модель

Alternative Flows:
4a. Пользователь нажимает Cancel → изменения отменяются
```

### Сценарий 3: Настройка API параметров

**Actor:** Пользователь  
**Goal:** Настроить параметры генерации под задачу  
**Preconditions:** Приложение открыто

```
Main Flow:
1. Пользователь открывает Settings (⚙️)
2. Пользователь изменяет параметры:
   - Temperature: двигает slider от 0.0 до 2.0
   - Max Tokens: вводит число или оставляет пустым
   - Stop Sequences: вводит последовательности через запятую
   - Response Format: выбирает Text или JSON chip
3. Пользователь нажимает Save
4. Настройки применяются к следующим запросам
5. Диалог закрывается

Alternative Flows:
2a. API Key пуст → показывается ошибка валидации
2b. Temperature вне диапазона → показывается ошибка
3a. Cancel → все изменения сбрасываются
```

## 5. Ограничения и Риски

### 5.1 Что НЕ реализовано

| Функция | Статус | Описание |
|---------|--------|----------|
| ❌ **Persistence** | Не реализовано | История чата и настройки НЕ сохраняются между сессиями. При перезагрузке страницы все данные теряются. |
| ⚠️ **Streaming** | Инфраструктура есть, не интегрировано | Streaming API реализован на уровне сети, но UI не показывает ответы в реальном времени (токен за токеном). |
| ❌ **Metrics Tracking** | Не реализовано | Нет отслеживания метрик (время ответа, токены, latency). Запланировано в ChatState.metrics. |
| ❌ **Reasoning Comparison** | Не реализовано | Нет сравнения ответов разных моделей. Запланировано в ChatState.reasoningComparison. |
| ❌ **Chat History Export** | Не реализовано | Нельзя экспортировать историю чата. |
| ❌ **Multiple Conversations** | Не реализовано | Только одна активная беседа за раз. |
| ❌ **System Prompts** | Не реализовано | Нельзя настроить system prompt для AI. |

### 5.2 Known Limitations

1. **In-Memory State Only**
   - Все данные хранятся в памяти браузера
   - Перезагрузка страницы = потеря всех данных
   - Требуется реализация localStorage persistence

2. **No Real-Time Streaming**
   - Пользователь видит полный ответ только после завершения генерации
   - Нет визуализации "печатания" ответа токен за токеном
   - Infrastructure существует, требует интеграции в UI

3. **Single Session**
   - Нет поддержки multiple chat sessions
   - Нельзя переключаться между разными разговорами
   - Нельзя сохранять именованные сессии

4. **No Offline Mode**
   - Приложение требует постоянного интернет-соединения
   - Нет кэширования ответов
   - Нет retry механизма при обрыве связи

### 5.3 Technical Constraints

1. **WASM Platform**
   - Приложение работает в браузере через Kotlin/Wasm
   - Ограничения браузерной среды (localStorage доступен, но не используется)

2. **API Dependencies**
   - Зависимость от внешнего API (Z.ai)
   - Требуется валидный API key для работы
   - Rate limits провайдера

3. **No Backend**
   - Нет серверной части для persistence
   - Все вычисления на клиенте
   - API key хранится в памяти (security risk)

## 6. Roadmap (что планируется)

### Phase 1: Persistence (Приоритет: HIGH)
**Цель:** Сохранение данных между сессиями

**Задачи:**
- [ ] Создать модуль `:core:storage`
- [ ] Реализовать `SettingsStorage` с localStorage backend
- [ ] Сохранять `ApiSettings` в localStorage
- [ ] Сохранять историю чата в localStorage
- [ ] Добавить миграцию данных при изменении структуры

**Ожидаемый результат:** Пользователь не теряет настройки и историю при перезагрузке

### Phase 2: Streaming Integration (Приоритет: HIGH)
**Цель:** Показ ответов в реальном времени

**Задачи:**
- [ ] Интегрировать `sendMessageStreaming()` в ChatStoreFactory
- [ ] Добавить состояние `streamingMessage` в ChatState
- [ ] Обновить UI для отображения partial messages
- [ ] Добавить кнопку "Stop generation"
- [ ] Оптимизировать производительность при streaming

**Ожидаемый результат:** Пользователь видит ответ токен за токеном в реальном времени

### Phase 3: Metrics Tracking (Приоритет: MEDIUM)
**Цель:** Отслеживание метрик запросов

**Задачи:**
- [ ] Добавить поле `metrics: List<MetricRecord>` в ChatState
- [ ] Собирать метрики: response time, tokens, latency
- [ ] Создать `MetricsDialog` компонент
- [ ] Добавить отображение метрик в UI
- [ ] Добавить экспорт метрик в CSV/JSON

**Ожидаемый результат:** Пользователь видит статистику по запросам

### Phase 4: Reasoning Comparison (Приоритет: MEDIUM)
**Цель:** Сравнение разных подходов к решению задач

**Задачи:**
- [ ] Реализовать `runReasoningComparison()` в ChatRepository
- [ ] Добавить 4 режима: Direct, Step-by-Step, Meta-Prompt, Expert Panel
- [ ] Создать `ReasoningDialog` с tabs
- [ ] Добавить `ComparisonTable` для результатов
- [ ] Показывать comparison только когда `isComplete == true`

**Ожидаемый результат:** Пользователь может сравнить разные подходы к одной задаче

### Phase 5: Enhanced Features (Приоритет: LOW)
**Цель:** Улучшение UX

**Задачи:**
- [ ] Multiple chat sessions с переключением
- [ ] Именованные сессии
- [ ] Export chat history (Markdown, JSON)
- [ ] System prompt configuration
- [ ] Keyboard shortcuts
- [ ] Dark/Light theme toggle

**Ожидаемый результат:** Улучшенный UX для power users

## 8. Конкурентные Преимущества

### Уникальность продукта

**1. Единый интерфейс для GLM-моделей**
- ✅ 4 модели в одном интерфейсе
- ✅ Быстрое переключение между моделями
- ✅ Сравнение power/cost ratio

**2. Простота использования**
- ✅ Минималистичный UI без лишних элементов
- ✅ Настройка через интуитивный dialog
- ✅ Markdown rendering из коробки

**3. Гибкая настройка параметров**
- ✅ Temperature control с visual feedback
- ✅ Max tokens limit
- ✅ Stop sequences support
- ✅ Response format selection (Text/JSON)

**4. WASM-based Architecture**
- ✅ Запуск в браузере без установки
- ✅ Кроссплатформенность
- ✅ Быстрая загрузка

### Конкуренты и дифференциация

| Продукт | Преимущества Z.ai Chat | Недостатки Z.ai Chat |
|---------|------------------------|----------------------|
| **ChatGPT Web** | - Multiple GLM models<br>- Open source<br>- Customizable parameters | - Менее известен<br>- Нет persistence |
| **OpenAI Playground** | - Простой интерфейс<br>- Бесплатный (со своим API key) | - Только GLM models<br>- Меньше функций |
| **Claude Web** | - Разные модели в одном UI<br>- Настройка temperature | - Другой провайдер<br>- Нет сравнения моделей |
| **Local LLM UI** | - Cloud-based (не требует GPU)<br>- Быстрый старт | - Зависимость от API<br>- Нет offline mode |

### Key Differentiators

1. **GLM Focus** — специализация на GLM-моделях, deep integration
2. **Developer-Friendly** — настройка всех параметров API
3. **Lightweight** — быстрый веб-интерфейс без установки
4. **Educational** — возможность сравнения моделей для обучения

## 9. Метрики Успеха

### Product KPIs

**1. User Engagement**
- **DAU (Daily Active Users):** Количество уникальных пользователей в день
  - Target: 100+ DAU после 3 месяцев
- **Messages per Session:** Среднее количество сообщений за сессию
  - Target: 5+ messages/session
- **Session Duration:** Средняя длительность сессии
  - Target: 10+ minutes

**2. Feature Adoption**
- **Settings Usage:** % пользователей, открывших Settings
  - Target: 40%+ users
- **Model Switching:** % пользователей, сменивших модель
  - Target: 30%+ users
- **Temperature Adjustment:** % пользователей, изменивших temperature
  - Target: 25%+ users

**3. Performance Metrics**
- **Response Time:** Среднее время ответа от AI
  - Target: < 3 seconds для простых запросов
- **Error Rate:** % запросов с ошибками
  - Target: < 5% error rate
- **Page Load Time:** Время загрузки приложения
  - Target: < 2 seconds

**4. User Retention**
- **Day 1 Retention:** % пользователей, вернувшихся на следующий день
  - Target: 30%+
- **Week 1 Retention:** % пользователей, вернувшихся через неделю
  - Target: 15%+
- **Month 1 Retention:** % пользователей, вернувшихся через месяц
  - Target: 10%+

**5. Technical Metrics**
- **WASM Load Time:** Время инициализации WASM модуля
  - Target: < 1 second
- **Memory Usage:** Потребление памяти браузером
  - Target: < 100 MB для 100 сообщений
- **API Success Rate:** % успешных API вызовов
  - Target: 95%+
